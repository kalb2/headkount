# API verification — 29 September 2026

Official Connecteam guides and endpoint OpenAPI definitions were reviewed during this update. Where the smart-group guide and the OpenAPI schema disagree, the request body follows the OpenAPI schema.

| Area                     | Verified contract                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Source                                                                                                                                                                                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Smart groups             | `GET /users/v1/smart-groups`. The guide names the array `data.smartGroups`; the OpenAPI schema names it `data.groups`. This app accepts either, including a successful empty array. A missing list is a parse failure. `401` and `403` are access failures and keep `requestId` when Connecteam sends one. No pagination parameters are documented.                                                                                                                                                                                                                                                                                                                                   | [Smart groups guide](https://developer.connecteam.com/docs/smart-groups), [Get smart groups](https://developer.connecteam.com/reference/get_smart_groups_users_v1_smart_groups_get)                                                                    |
| Create smart group       | `POST /users/v1/smart-groups`. Required: `name`, `groupSegmentId`, and `filters`. `filters` is an object with `operator` (`and` or `or`, default `and`) and `dropdownFilters`. Each dropdown filter uses `fieldId` and `optionIds`. The guide’s `filters[].customFieldId` array is not the OpenAPI contract and is rejected. An empty `dropdownFilters` array is sent when the operator does not choose membership rules. Success payload is `data` with `id`, `name`, and `groupSegmentId`, plus `requestId`. `409` is a name conflict; `400` covers an invalid segment, field, or option. Readback uses `GET /users/v1/smart-groups?id=`. The group schema does not return filters. | [Create smart group](https://developer.connecteam.com/reference/create_smart_group_users_v1_smart_groups_post)                                                                                                                                         |
| Smart group segments     | `GET /users/v1/smart-group-segments` reads `data.segments`. `POST /users/v1/smart-group-segments` requires `name` and `color` (`#RRGGBB`). The guide shows color as optional; the OpenAPI schema requires it. Response `data` includes `id`, `name`, and `color`.                                                                                                                                                                                                                                                                                                                                                                                                                     | [Create segment](https://developer.connecteam.com/reference/create_smart_group_segment_users_v1_smart_group_segments_post), [Get segments](https://developer.connecteam.com/reference/get_smart_group_segments_users_v1_smart_group_segments_get)      |
| Create jobs              | `POST /jobs/v1/jobs` takes an array. Parent jobs specify `instanceIds`; nested sub-jobs can have their own `assign` when `useParentData: false`. Names are limited to 128 characters. Blank coordinates are omitted.                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | [Create jobs](https://developer.connecteam.com/docs/create-jobs), [endpoint schema](https://developer.connecteam.com/reference/create_jobs_jobs_v1_jobs_post)                                                                                          |
| Read jobs                | List jobs with documented pagination; fetch individual sub-jobs through `GET /jobs/v1/jobs/{jobId}` and read `data.job`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | [Get jobs](https://developer.connecteam.com/reference/get_jobs_jobs_v1_jobs_get), [Get job](https://developer.connecteam.com/reference/get_job_jobs_v1_jobs__jobid__get)                                                                               |
| Repair                   | `PUT /jobs/v1/jobs/{subJobId}` includes `title`, unchanged `parentId`, and `useParentData`. Preserve writable `code`, `customFields`, `description`, `gps`, and `fenceSize` where applicable. Custom-field writes contain `customFieldId` and `value`, excluding response metadata.                                                                                                                                                                                                                                                                                                                                                                                                   | [Update endpoint schema](https://developer.connecteam.com/reference/update_job_jobs_v1_jobs__jobid__put)                                                                                                                                               |
| Inheritance              | Inherited sub-jobs cannot explicitly send `assign`, `gps`, or `description`; custom assignments require `assign`. Only parents already containing sub-jobs can receive more sub-jobs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | [Sub-jobs](https://developer.connecteam.com/docs/sub-jobs)                                                                                                                                                                                             |
| Users                    | Paginated GET supports `userIds`; PUT accepts an array of users and partial custom-field updates. User batch limit is 25. Employee updates use individual writes with fresh reads.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | [Get users](https://developer.connecteam.com/reference/get_users_users_v1_users_get), [Update users](https://developer.connecteam.com/reference/edit_users_users_v1_users_put), [Users overview](https://developer.connecteam.com/docs/users-overview) |
| Employee dropdown fields | `isMultiSelect` and `dropdownOptions` are read from current custom-field settings; dropdown values are arrays of `{id}`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | [Custom-field settings](https://developer.connecteam.com/reference/get_custom_fields_users_v1_custom_fields_get)                                                                                                                                       |
| Target instances         | Schedulers return `data.schedulers` / `schedulerId`; time clocks return `data.timeClocks` / `id`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | [Schedulers](https://developer.connecteam.com/reference/get_schedulers_scheduler_v1_schedulers_get), [Time clocks](https://developer.connecteam.com/reference/get_time_clocks_time_clock_v1_time_clocks_get)                                           |

The update guide’s table labels GPS and description “conditional/required,” but the sub-job guide and endpoint schema mark them optional when not inherited. The implementation preserves any existing values instead of inventing blanks or dropping them. It always provides the required assignment when custom settings are selected.

Application validation is deliberately stricter than the API for new door setup: at least one brand and a nonempty effective group selection for every new brand are required. Names, positive integer IDs, duplicate brands, latitude/longitude ranges, selected existing groups, new smart-group names, segment names and colors, dropdown filters, and target instances are checked server-side. No live account calls were used for this validation. Smart-group deletion is not exposed.
